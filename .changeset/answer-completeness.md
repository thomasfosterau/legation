Mark a `Client` answer that the replica gave for an uncovered read as partial (#653). `Client.completenessOf(rows)` returns `Option.some("complete")` for rows from a covered or server-answered `Client.query`, `Option.some("partial")` for an uncovered read the replica answered (offline, or over a transport without `read`), and `Option.none()` for an array no Client answered with. Each array `Client.observe` emits is marked the same way: partial until the read's windows are pulled, then emitted again as complete. The marker sits beside the rows, so the result's type and shape are unchanged, and a Svelte `useQuery` result's rows carry it too. A complete mark is only ever given to rows read after the pull marks that cover them: on each emission and each pull the Client reads the read's rows again, after the marks, rather than relabelling an array that may predate the pull. `ClientView` gains an optional `pulledChanges` stream, which the Client uses to judge a live read again after a pull, and an optional `queryRelated`, which reads a held relational read's current rows (a `Mirror` answers it from its host's rows). An engine-backed view's relational read now records pull marks under its relational key, as a pin with `include` does.
