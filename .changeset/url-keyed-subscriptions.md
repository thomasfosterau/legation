URL-keyed subscriptions over the mirror channel (ADR-0029 section 2, issue #159).

- `Client.subscribe` / `Client.unsubscribe` accept a JSON:API URL as well as a `Query.Read`. A Client built with the new `urls` option (`Client.UrlReads`: `parse(url)` and `canonical(read)`) parses the URL, plans the read and canonicalises it, so `subscribe(url)` and `subscribe(read)` of one query — and any non-canonical spelling of the URL (parameter order, a repeated `include` key, an API prefix, a `fields[]` projection) — share one ledger entry keyed by the canonical URL beside the subset hash. A URL the bridge refuses (an unknown collection, an unparsable filter, an undeclared edge) fails with a `QueryError` naming the offending parameter and registers nothing; a Client built without `urls` fails a URL call with a `QueryError`, never a defect. `Client.subscriptions` lists the canonical URLs of the explicit pins for devtools, and `Client.coverageOf` names the covering subscription's canonical URL (`Verdict.url`) when it has one. `Client.make`, `Client.connect` and `Client.fromView` take `urls`; `@legation/effect` itself does not know the URL grammar (ADR-0006), so `@legation/jsonapi` builds the seam from the node graph: `JsonApiQuery.urlReads(nodes)`.
- An explicit pin now registers its edge windows. `Client.subscribe(read)` with `include` runs the same relational registration `observe` runs — `view.related`, host-side over a connected engine and the scoped reconcile loop over an owned one — held open until the last pin releases, and records the edge selects on the ledger entry, so a read with `include` is covered by a pin that declared the edge (ADR-0029 rule 4). The commerce shell's `myCartItems` pin (`include: { variant: true }`) now syncs its edge window. Release stays symmetric with the pin count.
- Engine subscriptions are counted where two registrations can hold one window: `ClientView.fromEngine` and `EngineHost` register through `Subscriptions.counted(engine)`, so a relational read's own root subscription ending beside an explicit pin — or one relational read's foreign window beside another's — no longer drops the window from the engine's set-based subscription list. `Related.relatedWith` no longer dies when its initial pull fails (an offline `Client.make`): a failed pull only delays rows.
- The mirror protocol gains `SubscribeUrl` / `UnsubscribeUrl` (`{ mirrorId, url }`): a page with no `Client` posts them on the channel, and an `EngineHost` built with `nodes` and `urls` parses, plans and registers the URL's root and edge windows under that `mirrorId` — a thin adapter over the existing `Subscribe` and `SubscribeRelated`, refcounted and swept like any mirror's registrations. `ServiceWorkerHost.run` and `ElectedHost.run` forward `nodes` / `urls`; `ElectedHost`'s Client takes `urls` too.
- `Query.tryPlan(nodes, read)` is `Query.plan` with its `QueryError` as a typed failure.
