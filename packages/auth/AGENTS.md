# packages/auth — `@thomasfosterau/legation-auth`

The effect-auth bridge to legation's auth seams (#219): identity resolution, read scopes and the sign-out reset. Read the root [AGENTS.md](../../AGENTS.md) first. **Private** (`"private": true`): it is not published until the owner sets up its npm trusted publisher; `scripts/pack.mjs` (so `pack:check` and the release) skips private packages, and it carries no changeset.

## Boundary

- Imports from the workspace: `@thomasfosterau/legation` only (its `./internal` entry for types). Core gains nothing from this package and never imports effect-auth.
- **Peers:** `@thomasfosterau/effect-auth ^0.4.0` (the app configures its services, so there is one copy) and `effect ^4.1.0` (`catalogs.auth-peers`), because effect-auth 0.4.x peers `effect ^4.1.0`. This package's `effect` floor is 4.1.0; its tests are their own Vitest project (`auth`) so CI's "Tests (effect floor, auth)" runs them at it. effect-auth's `@thomasfosterau/effect-jsonapi` peer is optional and unused here.
- **Two entries.** `.` (`src/index.ts`, server side): `Principal`, `Resolver`, `ReadScopes`. `./client` (`src/client.ts`): `SignOut`. The client entry imports **no effect-auth runtime** (effect-auth's root barrel reaches `node:crypto`), only legation and `effect/crypto`'s `Digest`; effect-auth's session Atom is read by shape (`SignOut.SessionStore`, made by `SignOut.sessionStoreOf`). Keep it that way and check `dist/client.js` after a change.
- Written against effect-auth's core services (`SessionService`, `ApiKeyService`, `SessionResolution`, `ReadScope`), never its HTTP tier: it runs against an in-process effect-auth. Never guess effect-auth's API: read `node_modules/@thomasfosterau/effect-auth/dist/*.d.ts`.

## Invariants

- **Fail closed.** `Resolver` re-validates the request's credential on every resolve, and every failure — absent, unknown, expired, revoked or disabled credential, a store fault, a defect, a throwing header lookup — resolves to `Principal.anonymous`. It never fails the request and never returns a partially trusted principal. An interrupt is passed through, not converted. A request carrying an API key header is decided by the API-key plane alone.
- **Narrow, never widen.** `ReadScopes` translates effect-auth's scope exactly or not at all: an `Inexact` compilation, an untranslatable node (a `Compare` on text or booleans), an unmapped attribute, a literal of the wrong kind or out of its domain, and a failing or dying compile all become a typed `ScopeMappingError`, and the auth filter answers `Deny`. It never drops a conjunct and never falls back to `AllowAll`; only effect-auth's own `AllowAll` becomes legation's. Attribute coverage and set declarations are checked when the mapping is built (`ReadScopes.mapping` / `policy`), not per request, and `ReadScopes.bindingOf` derives the binding's kinds from the node, so a kind mismatch is a build-time `FieldKind` error.
- **The anonymous principal is `Anonymous::"anonymous"`** (`ReadScopes.principalRef`; effect-auth 0.3 refuses an empty id or type, so it cannot be `User::""`). It is not a `User`: policies scoped to the user type do not name it, one with no principal scope still applies, so a forbid meant to bind signed-out viewers must not be scoped to `User`. `principalRequest` gives it an empty slice (at most the action's entities) and never asks a resolver who it is. An API key gets no role (it carries no user record).
- **The anonymous principal owns nothing (#662).** An entity attribute of type `User` equals no `Anonymous` reference, so effect-auth compiles `resource.owner == principal` to false for it, whatever a row's owner field holds. `translate` is therefore exact for every principal (no narrowing of its own); `corpus-oracle.test.ts` checks row by row that it agrees with `matches`, the anonymous scope included.
- **Two-valued in, three-valued out.** effect-auth's predicate is two-valued (absent ⇒ `Eq` / `Compare` / `InSet` false); legation's is Postgres's three-valued logic (ADR-0028). Every such atom is translated as `field IS NOT NULL AND atom`, so the translated scope admits exactly the rows effect-auth's `ReadScope.matches` admits; `corpus-oracle.test.ts` checks that row by row. Instants are `DateTime.formatIso` (= `Date#toISOString`) of whole milliseconds in years 0000–9999.
- **Credentials are never logged or carried.** A principal holds no token, key or hash (a validated session's `id` is its stored digest, but the principal still carries no session id). Log lines name only the plane and failure kind (resolver) or the collection and reason (scopes); `ScopeMappingError` messages name collections, attributes and policy ids.
- **Sign-out quarantines.** `SignOut.onSessionChange` adopts the next session's fingerprint with `Client.reset` (#212): a superseded user's unpushed journal is quarantined, neither flushed nor discarded. The decision compares with the replica's stamp, not `previous`. `SignOut.follow` subscribes it to a session store over effect-auth's session Atoms, skips pending states (a reload is not a sign-out) and adopts in order. Fingerprints are `legation-auth:sha256:<hex>` of the user id under a domain separator, never the id.

## Tests

`src/__tests__/` (Vitest project `auth`). `harness.ts` runs effect-auth in process: `SessionService` and `ApiKeyService` over effect-auth's testing memory stores and a memory `ApiKeyStore`, with stores that fail (`AuthError`) or die on demand.
